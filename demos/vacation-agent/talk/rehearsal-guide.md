# חזרה להרצאה: אותו סוכן, תנאים חדשים

הסיפור מסתיים בדקה 25. דקות 25–30 לשאלות. שקפים 19–21 הם נספח בלבד.

## פתיחת הבמה

האתר הוא Somewhere, אתר חופשות בדוי רגיל. כל השליטה וה-trace בטרמינל. הציגו חלון דפדפן וחלון טרמינל זה לצד זה. אין באתר כפתורי מגיש, כלי סוכן או אפשרות תשלום.

מתיקיית הריפו, לאחר `npm ci` והתקנת Chromium:

```sh
HEADED=1 npm run demo:vacation -- happy --interactive --site-url https://vacation-agent-rehearsal.vercel.app
```

אמרו בתחילת ההדגמה: ״הבחירות בחזרה הזאת מתוסרטות. הדפדפן והבדיקות רצים באמת. אין כאן קריאות מודל או AWS.״ הכתובת הציבורית מופיעה בפלט. רשמו את `run ID` והראו שהוא נשאר זהה כשמשנים תנאים.

## חזרה אחת עם שתי התערבויות

1. בשקף 4: `next`, ואז `next`. הסוכן בוחר לפתוח A, לוחץ ומציג פרטים. `next` שלישי משאיר `before_click` עם `select_hotel`. עוד לא נלחץ כפתור בחירת המלון.
2. בשקף 5: הקהל מוכר את החדר האחרון. הקלידו `sold-out A`, ואז `next`. העולם משתנה, גרסת ההחלטה נשארת ישנה, וה-trace מציג `world_changed`. אין לחיצה. השאירו את הריצה בהשהיה בזמן ההסבר.
3. בשקף 14: המשיכו עם `next` נקודה בכל פעם. בחירה לחזור לתוצאות, לחיצה, בחירה לפתוח C, לחיצה. `next` נוסף משאיר את בחירת C לפני הלחיצה. C נגיש ובתקציב הנוכחי, אבל עדיין אין הזמנה.
4. בשקף 15: `budget 500`, ואז `next`. גם בחירת C מתיישנת. `run` ממשיך עד `no_match`. הסוכן ממתין באותה ריצה; הוא לא מוזיל מלון ולא מבטל נגישות בעצמו.
5. הקלידו `restore-hotel A`, `budget 600`, ואז `run`. הסוכן קורא את המצב החדש, מחשב מחדש החרגות, ובוחר A. אותו run ID ואותו דפדפן. הוא מסיים בסיכום לפני תשלום, וכפתור התשלום מושבת.

אם הקהל בחר תקציב ראשון, הורידו אותו בשלב 2, הציגו no_match ואז שחזרו. זו גם אותה ריצה. אל תריצו תרחיש CLI חדש כדי להעמיד פנים שהתנאים השתנו בתוך ריצה.

## פקודות מגיש

| פקודה | התנהגות |
|---|---|
| `next` | משחררת נקודת עצירה אחת, לפני החלטה או לפני לחיצה |
| `run` | ממשיכה עד סיום או no_match |
| `pause` | עוצרת בנקודת העצירה הבאה |
| `sold-out A` / `restore-hotel A` | משנה זמינות בנקודת העצירה בלי לבנות מחדש את הדפדפן |
| `budget 500` / `budget 600` | משנה את התנאים שהקוד בודק |
| `stop` | מסיימת את הריצה ומבטלת המתנה מקומית להחלטה |
| `reset` | בזמן ריצה, מתחילה ריצה חדשה עם מזהה חדש באותו דפדפן |

Ctrl-C, SIGTERM וסגירת הקלט מסיימים דרך ניקוי הדפדפן. החלטה מאוחרת לא נלחצת אחרי Stop או Reset. `stop` אינו הבטחה לבטל חיוב אצל ספק מודל שכבר קיבל בקשה. אחרי סיום רגיל ה-CLI נסגר; פותחים ריצה חדשה לחזרה נוספת.

## גיבוי ללא אינטרנט

בנו את האתר מראש:

```sh
npm run build:site --workspace=@tomerwave/vacation-agent
python3 -m http.server 4173 --directory demos/vacation-agent/dist/site
```

בטרמינל נוסף:

```sh
HEADED=1 npm run demo:vacation -- happy --interactive --site-url http://localhost:4173
```

האתר והתמונות מקומיים. אותן פקודות ואותה לולאה. הגיבוי המהיר ביותר: השמיטו `--site-url` ל-HTML בזיכרון; תמונות האווירה בגרסה הזאת עשויות לדרוש רשת. אם Chromium אינו זמין, `examples` מכיל ארבעה פלטים מוקלטים, ו-`talk/verification` מכיל התערבויות שנבדקו. אמרו שזה replay מוקלט. אל תבזבזו זמן במה על התקנות.

## מסלול חי

Jev, AgentCore Browser ו-Strands נשארו בקוד ואינם מוחלפים בבחירה מתוסרטת כשהדגל שלהם מופעל. יש לשלב `--interactive` ו-`--site-url` עם הדגלים הרלוונטיים רק אחרי אישור העלויות וחזרה מול החשבון:

```sh
HEADED=1 npm run demo:vacation -- happy --interactive --site-url https://vacation-agent-rehearsal.vercel.app --chooser jev
npm run demo:vacation -- happy --interactive --site-url https://vacation-agent-rehearsal.vercel.app --chooser jev --browser agentcore --planner strands
```

הקריאות החיות לא נבדקו כאן. בדיקות SDK מדומות ובניית מתכנן אינן הוכחה להרצה מול השירותים. במסלול AgentCore הקהל צופה בקישור Live View. אל תשתמשו ב-localhost לדפדפן בענן.
